# RABR and evaluation protocol

## Candidate generation and grounding

Each generation sees only the session intent and strictly earlier item interactions. It returns a JSON object with an `items` list of descriptions. Invalid JSON contributes an empty generation; it does not trigger a target-assisted repair. A generation retains at most `v_max` descriptions. Catalog title vectors and description vectors are normalized, and each description is assigned to its nearest catalog item if raw cosine similarity is at least `tau`. Ties follow catalog order. Accepted similarity is rescaled to `[0,1]`; multiple descriptions mapping to the same item are averaged within that generation.

The finite budget and threshold grids are fixed in configuration before calibration. Every calibration session receives the largest requested number of generations. Smaller budgets reuse its prefixes. Checkpoints store each round, generation seed, input hash, raw output, parse status, grounded scores, and measured generation cost.

## Score definitions

The primary `equation8` implementation follows the manuscript's numbered equation: `gamma × mean grounding similarity + (1-gamma) × user relevance`. The grounding mean is over generations containing that item. User relevance is rescaled cosine similarity between the catalog title and the intent/history text.

The appendix and RQ3 discuss frequency, although Equation 8 does not contain a frequency term. The explicitly named `frequency_similarity` reconstruction defines `f` as the fraction of generations containing the item, `a` as its matching-generation mean grounding similarity, and `u` as user relevance. Its score is `gamma*f + (1-gamma)*(a+u)/2`. This is a specified experimental interpretation of the appendix, not an additional numbered equation from the paper.

`without_frequency` uses `(a+u)/2`; `without_similarity` uses `f`. These two ablations require `frequency_similarity`. `multi_sample_fixed_k` ranks by frequency and retains a training-derived K. `fixed_k` uses the selected score definition with fixed K. `fixed_threshold` uses the configured threshold. These fixed construction variants use the configured maximum budget and are marked `uncertified_ablation`; they do not claim risk certification.

## Calibration

The bounded loss is `1-F_beta` on deduplicated catalog item sets. For each budget/threshold pair, the calibration mean loss is converted to a one-sided Hoeffding/KL p-value. Bonferroni correction divides delta by the full grid size. A pair passes only when its p-value is no greater than that cutoff. Selection takes the smallest passing budget, then the largest passing threshold at that budget.

No passing pair yields a terminal `no_certified_pair` receipt. The primary method does not substitute an empty set, fixed threshold, best empirical pair, or uncertified prediction. Risk-control interpretation is conditional on the theorem's sampling and fixed-grid assumptions; a chronological split alone does not establish those assumptions.

The default RQ1 parameters are alpha=delta=0.05, beta=1, gamma=0.5, budgets 1–10, thresholds 0–1 in increments of 0.05, raw cosine tau=0, and `v_max=8`. Gamma, tau, the finite grids, encoder, and description limit are explicit reconstruction choices where the manuscript does not provide a fully executable specification. RQ2–4 parameter overrides are recorded in every job configuration. A calibration-fraction sweep is an additional protocol sensitivity, with membership determined by a seed/session hash before inspecting losses.

## Separation of data

Training targets are available to trainable methods, training pattern mining, teacher example construction, and train-only reward simulators. Validation selects learned checkpoints and early stopping. RABR uses calibration targets only to select its budget and threshold. Prediction functions receive an allowlisted record containing session identity, time, optional user ID, intent, and safe history fields. They never receive test target fields. Test metrics are computed after label-free predictions have been committed to disk.

The prepared-data import preserves the supplied calibration and test memberships, while taking a final chronological fraction of the original training partition for validation. This produces a new training protocol relative to any earlier experiment that used the entire original training partition. Historical targets and results must not be represented as having been generated by this repository without rerunning and validating their identities.

The default fixed output size is the rounded training-target median, bounded to 2–8 by the data protocol. An explicit `fixed_k` can override it. `paper_rabr_mean` instead takes a completed matching RABR run's calibration mean bundle size, rounds half-up, and uses at least one item. It requires the same domain, seed, and data manifest. A missing certified reference blocks dependent comparisons. Test bundle sizes never choose a baseline's K.

## Evaluation and persistence

Metrics are macro Precision, Recall, HitRatio, F-beta, mean `1-F_beta` risk, and bundle size. Empty predictions score zero Precision/Recall/F-beta and risk one. Invalid or hallucinated catalog IDs are not counted as correct predictions. Every test session remains in the denominator. Duplicate IDs are removed with counts retained in the per-session record.

An exclusive per-run lock prevents concurrent writers. The append-only checkpoint binds rows to data, config, code, seed, method, domain, and model inventory. Only an unterminated final checkpoint line is discarded after interruption. A completed receipt hashes the output artifacts and fitted model files. Modified inputs or artifacts require a new output directory; they are not silently accepted as completed work.

Cost records distinguish the current attempt from durable round and prediction costs. Uncommitted work lost before checkpointing is not reconstructed. Local model inventories record names, sizes, and modification times, rather than asserting weight-level SHA verification. Keep pretrained model snapshots immutable throughout a suite.

The repository's queue runs on one allocated host with bounded retries. It preserves completed work and serializes one process per requested GPU. Cluster allocation, cross-host admission, and SSH access remain the deployment environment's responsibility.
